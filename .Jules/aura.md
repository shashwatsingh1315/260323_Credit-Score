## 2025-05-18 - Replacing Arbitrary Magic Numbers with Strict Base-4/Base-8 Tokens
**Learning:** The codebase contains numerous scattered instances of arbitrary bracket notation in Tailwind classes (e.g., `w-[200px]`, `h-[50vh]`, `p-[2px]`). This practice fundamentally breaks the uniform scaling of the design system, causing inconsistencies in component alignment and padding.
**Action:** Ban all arbitrary bracket notation for standard layout properties (width, height, padding, margins, positioning) in favor of predefined Tailwind sizing tokens (e.g., `w-48` instead of `w-[200px]`, `w-px` instead of `w-[1px]`, `p-0.5` instead of `p-[2px]`). Any required dynamic scaling must use explicit CSS variables rather than hardcoded magic numbers. This rule has been formalized in `DESIGN_STYLE.md`.
