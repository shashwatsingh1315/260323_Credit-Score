## 2024-06-08 - Baseline Aesthetics Tokenization
**Learning:** Legacy styling in CSS modules currently heavily relies on non-standard, hardcoded hex values (e.g., `rgba(255, 255, 255, 0.05)`, `#f8fafc`) and custom CSS variables (`--bg-primary`, `--text-muted`, etc.) which bypass our Tailwind token infrastructure. This fragments the dark mode configuration and creates a "mushy" aesthetic that isn't cleanly driven by HSL-based Tailwind scales.
**Action:** Replace all custom CSS hex variables (`--bg-primary`, `--text-muted`, etc.) in `src/app/globals.css` with semantic Tailwind HSL counterparts (e.g., `--background`, `--muted-foreground`). Update `page.module.css` files across the app (`src/app/page.module.css`, `src/app/policy/page.module.css`, `src/app/cases/[id]/page.module.css`, `src/app/login/page.module.css`, `src/app/admin/page.module.css`, `src/app/cases/[id]/board/page.module.css`) to map these legacy variables directly into `hsl(var(--xyz))` tokens or swap `rgba` backgrounds for utility class usage (`bg-white/5`).
