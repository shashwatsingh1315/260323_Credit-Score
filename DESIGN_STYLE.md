# DESIGN_STYLE.md\n\n## 📐 The Target Aesthetic\nAura enforces a premium, highly refined standard. The application must be uniform, clean, scalable, and built strictly on semantic design tokens rather than chaotic hardcoded values. The underlying design language draws inspiration from the rigid standards of top-tier products like Uber, Linear, and Apple: purposeful whitespace, strict typography constraints, standard radii, semantic layout primitives, and pure-token color mappings.\n\n## ⚙️ Design Token Scale\n### Global Theme Variables\nLegacy `--bg-*` / `--text-*` / `--accent-*` tokens must be mapped to semantic HSL strings compatible with Tailwind CSS.\n\n- `--background`: Base background color (Primary)\n- `--card`: Surface color for components/widgets\n- `--popover`: Elevated background for tooltips and menus\n- `--primary`: Primary action color\n- `--muted`: Subtle surfaces or deactivated items\n- `--accent`: Active/hover highlights\n- `--border`: Standard UI borders\n- `--input`: Form control borders\n\n### Layout & Spacing (Base-4/8 System)\nA strict adherence to `p-*`, `m-*`, `gap-*`, etc. Arbitrary pixel/bracket values (`[17px]`, `[50vh]`) are considered **bad practice** and technical debt.\n\n- `p-2` (8px), `p-4` (16px), `p-6` (24px)\n- `gap-2` (8px), `gap-4` (16px)\n- `w-px`, `h-px` for 1px lines\n\n### Typography Hierarchy\nDo not use arbitrary bracket text styling (e.g. `text-[10px]`). Use standardized tailwind sizes:\n\n- `text-tiny`: `10px` / `14px` line-height\n- `text-micro`: `11px` / `16px` line-height (if added to tailwind config)\n- `text-xs`: `12px`\n- `text-sm`: `14px`\n- `text-base`: `16px`\n\n### Colors in the wild\n- Any HEX value hardcoded in a `.tsx` file (e.g. `bg-[#141414]`) must be stripped and replaced with `bg-background` or similar.\n- Avoid standard Tailwind colors like `gray-900` or `blue-500` - instead use the semantic tokens defined above (e.g. `text-muted-foreground`, `bg-primary`, `border-border`).\n
